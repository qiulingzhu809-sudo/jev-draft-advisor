# Jev Draft Advisor · macOS 草稿建议助手

在 Codex 输入草稿后按 `Control+J`，通过 TypeSafe/Jev 分类任务，在半透明浮窗中推荐模型和推理强度。最终模型选择由用户手动完成。

这是实验性的独立菜单栏助手，非 OpenAI 或 TypeSafe 官方产品。目前以源码方式运行，自动读取的兼容性取决于 Codex 和 macOS 版本，尚未在所有环境验证。它不会自动提交 Codex 消息或自动切换模型。

## 功能

- 快捷键触发分析，显示模型及推理强度建议。
- 浮窗可拖动，右键可固定/取消固定位置、隐藏或退出。
- 隐藏后程序继续驻留，下次触发分析可再次显示；退出后需重新启动程序。
- 优先通过 macOS 辅助功能读取文本，失败时尝试键盘复制回退。

## 安装与 API Key 配置

需要 macOS、Codex 桌面应用、Node.js 20.6 或更新版本（推荐当前 LTS），以及包含 `swiftc` 的 Xcode Command Line Tools。Windows/Linux 暂不支持此菜单栏助手。

1. 下载或克隆本仓库，在终端进入仓库根目录。
2. 若尚未安装编译工具，运行 `xcode-select --install`，按系统提示完成安装。
3. 安装依赖。草稿助手不需要 Chromium，可跳过上游浏览器组件下载：

   ```bash
   JEV_BROWSER_SKIP_BROWSER_DOWNLOAD=1 npm ci
   ```

4. 从 [TypeSafe 控制台](https://console.typesafe.ai/settings/keys) 获取自己的 API Key，创建本地配置：

   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

5. 用本地编辑器打开 `.env`，填入真实值：

   ```dotenv
   TYPESAFE_API_KEY=你的_TypeSafe_API_Key
   ```

6. 启动助手：

   ```bash
   npm run draft-advisor
   ```

首次启动会编译 `.build/jev-draft-advisor`，终端保持运行，菜单栏出现 Jev。每位用户使用自己的 Key 和 TypeSafe 账户额度，仓库不提供共享 Key。不要将真实 Key 粘贴到 Issue、聊天、截图或演示录屏中。

当前 Key 以明文存储在本机 `.env` 中，由 Node 子进程读取，尚未接入 macOS 钥匙串；具备本机文件访问权限的软件仍可能读取它。启动脚本要求项目根目录存在 `.env`，尚无图形化设置界面。

## 权限与使用

在「系统设置 → 隐私与安全 → 辅助功能」允许实际运行的 `jev-draft-advisor`。若列表中没有它，可通过添加按钮定位仓库内的 `.build/jev-draft-advisor`；文件选择器中可用 `Command+Shift+G` 输入路径。系统可能根据启动方式将授权关联到终端应用，请根据实际提示检查。

授权后退出并重新启动助手。若重新编译后权限不再生效，检查条目是否对应当前程序，必要时移除旧条目并重新添加。不要仅凭 AX 错误码判断必然是权限问题。

1. 点击 Codex 草稿输入框，输入文字，让光标留在其中。
2. 按 `Control+J`，等待浮窗显示建议。
3. 按需在 Codex 中手动切换模型和推理强度。

当前代码不截图、不做 OCR，无需为本助手开启屏幕录制权限，也无需完整磁盘访问权限。辅助功能权限本身允许较广泛的 UI 访问与控制，请只授权你信任的构建。

## 隐私与数据流（使用前请阅读）

**触发分析时，捕获的草稿正文会发送到 TypeSafe/Jev 服务，而非只在本机处理。**「不自动发送 Codex 消息」不代表草稿不会离开电脑。

数据流：快捷键/菜单触发 → 本机读取文本 → Node 子进程调用 TypeSafe SDK → TypeSafe/Jev 分类 → 本机显示推荐。Key 用于 API 身份认证。助手代码没有主动将草稿提交给项目维护者或 GitHub；服务提供方的数据保存、日志和处理方式以其条款和隐私政策为准，本项目不承诺服务端零留存。

- 没有持续记录每次键入；读取发生在用户主动触发时。
- 助手代码不主动保存草稿历史，正常输出仅包含建议；错误信息可能显示服务端返回内容。提交日志前请检查并脱敏。
- 不要分析含密码、API Key、客户隐私、未获授权的公司代码等敏感信息的草稿。当前没有自动脱敏功能。
- AX 读取失败时，助手会向 Codex 进程发送 `Command+A`、`Command+C`，临时使用系统剪贴板，然后尝试恢复原有剪贴板数据，并发送右方向键取消全选。选择范围和光标位置可能变化。
- **复制回退目前仅确认应用身份，不能可靠确认焦点必然位于草稿框。** 如果焦点在搜索框或历史消息，可能读到并发送错误文本。使用前务必点击草稿框；当前没有发送前预览确认。
- 剪贴板恢复不构成绝对保证：程序异常退出、复制延迟或同时操作剪贴板可能造成干扰；剪贴板历史工具也可能记录临时复制的草稿。对敏感材料请勿使用当前自动读取流程。

## 当前限制

- 读取适配仅针对 `com.openai.codex` 及其辅助进程，不是全应用文本助手。
- 快捷键、透明度及模型映射目前在源码中配置；窗口位置和固定状态不会跨进程保存。
- 推荐基于 Jev 分类加人工规则，不是经完整基准验证的质量或费用保证。模型名称、可用性和推理档位需以实际账户为准。
- 浮窗使用默认 balanced 偏好；代码中的 cost/speed/balanced 尚无完整的差异化选型策略。价格字段是静态参考值，不是实时价格或单次任务报价。
- 依赖 Node 和本地 Swift 编译，目前不提供已签名、公证的安装包。
- 单元测试通过不代表真实 Codex 焦点读取已在所有版本验证。
- 分析中隐藏浮窗，结果返回时仍可能重新显示；彻底停止请选择退出。

## 常见问题

| 情况 | 检查方式 |
| --- | --- |
| 缺少 `.env` 或 API Key | 在仓库根目录复制 `.env.example`，填写自己的 Key |
| `swiftc` 不存在 | 安装 Xcode Command Line Tools |
| 快捷键无响应 | 查看是否提示快捷键冲突，确认没有重复运行旧进程 |
| 读不到草稿 | 检查辅助功能权限，点击有文字的草稿框后重试；应用已聚焦不等于输入框可读取 |
| 分析失败 | 检查 Key 有效性、TypeSafe 额度、网络和错误信息；公开日志前脱敏 |
| 修改后仍是旧行为 | 退出旧 Jev 进程后重新运行启动命令 |

## 发布与贡献时保护密钥

`.gitignore` 排除了 `.env`、`.env.*`（保留 `.env.example`）、构建目录、依赖及测试缓存。但忽略规则不会清除已提交历史，也不会过滤手工创建的 ZIP 文件。

- 只提交不含真实密钥的 `.env.example`，不提交个人 `.env`。
- 提交前检查 `git status --short`、`git diff --cached` 和历史中的敏感信息。启用可用的 GitHub secret scanning / push protection，但不要假设它识别所有 Key。
- 发布源码压缩包优先使用经过检查的 Git 提交归档；发布二进制时检查产物，不要把整个工作目录打包。
- CI 使用模拟响应运行测试。若必须在线测试，通过 GitHub Actions Secrets 提供专用测试凭据，不写入仓库、日志或发布包。
- 发现 Key 曾公开泄露时，立即在服务商处撤销/轮换，之后再处理 Git 历史与相关附件。
- 提交 Issue 请提供系统和 Codex 版本、触发步骤及脱敏错误，不要附带真实草稿、Key 或完整个人配置。
